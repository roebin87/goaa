# 01 · GOAA 架构核心工作原理
> **语义形态**：机语义（机制翻译层·How）

> 本文档公开 GOAA 架构核心的设计原理与工作流程。完整实现细节暂未开源，但设计原理完全公开。

## 一、五层架构与依赖关系

GOAA 采用自底向上的五层架构，每一层依赖下一层，治理不绑定特定模型与执行框架。

```
┌─────────────────────────────────────────┐
│  第五层 · 场景应用层                     │
│  （书稿生产/自举开发/知识管理/...）      │
├─────────────────────────────────────────┤
│  第四层 · 执行加挂层                     │
│  （多角色协作/外部工具调用/执行框架）    │
├─────────────────────────────────────────┤
│  第三层 · 核心机制层                     │
│  （启动/收摊/歧义治理/记忆装载/复用）    │
├─────────────────────────────────────────┤
│  第二层 · 规则与记忆层                   │
│  （规则分类/生效闸门/四层记忆/蒸馏）     │
├─────────────────────────────────────────┤
│  第一层 · 宪法与物理底座层               │
│  （基本法/设计原理/文件系统/权限隔离）   │
└─────────────────────────────────────────┘
```

**依赖原则**：
- 自底向上依赖，上层不得绕过下层直接操作
- 治理逻辑集中在第一至第三层，第四层以上为执行加挂
- 模型与执行框架在第四层可替换，核心治理层不受影响

## 二、宪法层→规则层→机制层→执行层的装载序列

GOAA 的启动装载遵循严格的序列，确保治理先于执行：

```
第 0 步：定位身体（工作区锚定）
    ↓
第 1 步：读宪法（先立规矩）
    ├─ constitution/basic_law.md（基本法·强制层读取项）
    └─ constitution/design-principles.md（设计原理·Why+How 一体）
    ↓
第 2 步：读身份（identity/ 三文件 + 主人档案）
    ├─ SOUL.md（灵魂·核心价值观与边界）
    ├─ IDENTITY.md（身份·角色定位与能力边界）
    └─ USER.md（主人档案·主人偏好与工作习惯）
    ↓
第 3 步：读蒸馏（_Memory/distill/·首次为空则建空档）
    ↓
第 4 步：跑启动序列（mechanisms/startup.md）
    ├─ 指令双检（人语义/机语义双检）
    ├─ 打卡（启动日志记录）
    └─ 校验器自检（validator.py）
    ↓
第 5 步：记忆校验（validator.py --memory）
    ↓
就绪：响应主人指令
```

**装载原则**：
- 宪法先于身份，身份先于记忆，记忆先于执行
- 任何一步不满足即停止并汇报，不得跳过
- 首次激活时，主人档案不存在则触发 onboarding 引导

## 三、管执分离的物理实现

GOAA 的"管执分离"（治理权与执行权分离）通过文件系统的物理隔离实现：

### 3.1 治理文件（只读/人控）

| 文件/目录 | 权限 | 说明 |
|-----------|------|------|
| constitution/ | 机侧只读 | 宪法层，仅主人可修改 |
| rules/ | 机侧只读 | 规则层，经生效闸门后由主人确认 |
| _Memory/history/ | 只追加 | 史书层，只追加不删改 |
| identity/主人档案.md | 机侧只读 | 主人档案，仅主人可改 |

### 3.2 执行文件（可写/机控）

| 文件/目录 | 权限 | 说明 |
|-----------|------|------|
| _Memory/snapshot/ | 可写 | 快照层，每次会话自动生成 |
| _Memory/index/ | 可写 | 索引层，自动维护检索索引 |
| _Memory/distill/ | 可写（收摊时） | 蒸馏层，收摊时由 AI 生成、主人确认 |
| 工作区临时文件 | 可写 | 执行过程中的临时产物 |

### 3.3 物理钩子（HOOKS）

管执分离通过"物理钩子"强制执行：
- **启动钩子**：启动时必须读取宪法层，否则拒绝执行
- **收摊钩子**：收摊时必须执行五钩（备份→蒸馏→日志→论语→报告）
- **规则生效钩子**：规则写入必须经过四道校验（存在性/语义/引用/格式）
- **权限钩子**：治理文件标记为机侧只读，AI 不得直接修改

> **内部实现说明**：目录只读权限强制、规则语义深度校验等内部定制能力暂未开源。开源版 validator.py 提供通用结构校验（存在性硬检+语义同步+YAML Schema+死链检查）。

## 四、模型无关性设计

GOAA 的核心治理层与具体 AI 模型无关：

- **模型在第四层**：AI 模型作为执行体在第四层加挂，可替换
- **治理逻辑在文件中**：所有治理规则、记忆、机制都以纯文本文件存在，不依赖特定模型的 API
- **部署指令通用**：DEPLOY.md 的部署指令可发给任何具备本地文件读写能力的 AI 助手
- **记忆可迁移**：四层记忆都是纯文本文件，可迁移到任何 AI 平台

## 五、设计原理与学术对应

| 架构设计 | 学术论文对应 | 核心公理 |
|---------|------------|---------|
| 宪法层先于执行 | 决断权公理（公理一） | 人保有 100% 最终决断权 |
| 文件系统物理底座 | 文件本体公理（公理二） | 文件是记忆与规则的权威载体 |
| 管执分离物理隔离 | 治理与执行分离原则 | 治理权归人，执行权可授权机器 |
| 模型无关性 | 主权与执行权分离 | 机制/授权/裁决归人，执行可替换 |
