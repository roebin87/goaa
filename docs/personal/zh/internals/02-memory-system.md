# 02 · GOAA 四层记忆体系工作原理

> 本文档公开 GOAA 四层记忆体系的设计原理与工作流程。完整实现细节暂未开源，但设计原理完全公开。

## 一、为什么需要四层记忆

AI 模型本身无持久记忆——每次对话结束，上下文就丢失了。GOAA 通过文件系统构建四层记忆体系，解决"AI 记不住"的核心问题。

**记忆不是存储，是治理工具**。GOAA 的记忆体系不仅是"存东西"，更是治理工具——它承担三大治理功能（见第三节）。

## 二、四层记忆分工与数据流

```
┌──────────────────────────────────────────────────────┐
│  第一层 · 史书层（History）· 只追加不删改            │
│  _Memory/history/ · 完整对话记录+日志+论语           │
│  权限：只追加（append-only）· 哈希基线防篡改         │
├──────────────────────────────────────────────────────┤
│  第二层 · 快照层（Snapshot）· 每次会话自动生成       │
│  _Memory/snapshot/ · 会话结束时的完整状态快照        │
│  权限：可写·自动生成·可回溯                           │
├──────────────────────────────────────────────────────┤
│  第三层 · 索引层（Index）· 自动维护检索索引          │
│  _Memory/index/ · 关键词/主题/时间/规则引用索引      │
│  权限：可写·自动维护·按需检索                         │
├──────────────────────────────────────────────────────┤
│  第四层 · 蒸馏层（Distill）· 收摊时生成·主人确认     │
│  _Memory/distill/ · 精华提炼·决策共识·待办·规则变更  │
│  权限：AI 生成·主人确认·启动时轻装载                  │
└──────────────────────────────────────────────────────┘
```

### 2.1 数据流

```
对话进行中
    ↓
史书层：实时追加（完整记录+日志）
    ↓
会话结束（收摊）
    ├─ 快照层：生成本次会话完整状态快照
    ├─ 索引层：更新检索索引
    └─ 蒸馏层：AI 生成精华提炼 → 主人确认 → 落盘
    ↓
下次启动
    ├─ 轻装载：读蒸馏层（精华，快速恢复上下文）
    └─ 深装载（按需）：通过索引层检索 → 从史书层/快照层读取详情
```

### 2.2 各层详细说明

| 层 | 内容 | 生成时机 | 装载策略 | 保留策略 |
|----|------|---------|---------|---------|
| 史书层 | 完整对话记录、操作日志、论语（重要决策记录） | 实时追加 | 不主动装载，按需检索 | 永久保留（只追加） |
| 快照层 | 每次会话结束时的完整工作区状态 | 收摊时自动生成 | 不主动装载，回溯时读取 | 保留最近 N 次（可配置） |
| 索引层 | 关键词、主题、时间、规则引用的检索索引 | 收摊时自动更新 | 启动时装载索引摘要 | 持续更新 |
| 蒸馏层 | 精华提炼、决策共识、待办、规则变更、关键记忆 | 收摊时 AI 生成、主人确认 | 启动时轻装载（必读） | 持续迭代，旧版本归档 |

## 三、记忆治理三功能

GOAA 的记忆体系不仅是存储，更是治理工具，承担三大治理功能：

### 3.1 锚定抗衰减（Anchoring against Decay）

**问题**：AI 模型的上下文会衰减——对话越长，早期的规则和约定越容易被遗忘。

**解法**：蒸馏层在每次启动时被轻装载，将核心规则、决策共识、关键记忆重新注入上下文，对抗衰减。

**效果**：固化规则跨会话无衰减（与学术论文中 Liu 2026 报告的"无治理时 94%→61% 衰减"形成对照）。

### 3.2 认知闸门（Cognitive Gatekeeping）

**问题**：不是所有记忆都值得被装载——无关信息会占用上下文、干扰判断。

**解法**：蒸馏层是经过主人确认的"精华"，启动时只装载蒸馏层，不装载完整史书。需要详情时通过索引层按需检索。

**效果**：上下文空间被高价值信息占据，低价值信息不干扰判断。

### 3.3 算力聚焦（Compute Focusing）

**问题**：如果每次启动都装载完整记忆，会消耗大量 token（算力=成本）。

**解法**：启动时只装载蒸馏层（精华，通常几千 token），按需从史书层/快照层检索详情（可能几万 token）。

**效果**：日常运行成本极低（启动只需几千 token），只有需要回溯时才消耗更多。

## 四、记忆装载策略

### 4.1 启动轻装载

启动时按以下顺序装载：
1. 宪法层（basic_law + design_principles）
2. 身份层（SOUL + IDENTITY + USER + 主人档案）
3. 蒸馏层（_Memory/distill/ 最新蒸馏）
4. 索引摘要（_Memory/index/ 索引摘要）

**不装载**：史书层完整记录、快照层完整快照。

### 4.2 按需深装载

当主人或 AI 需要历史详情时：
1. 通过索引层检索关键词/主题/时间
2. 定位到史书层或快照层的具体文件
3. 读取相关片段（不是全部）

### 4.3 收摊五钩

每次会话结束（收摊）时，必须执行五钩：

```
第 1 钩 · 灵魂备份：备份 identity/ 和 constitution/ 到 _Memory/history/
    ↓
第 2 钩 · 蒸馏：AI 生成本次会话精华 → 主人确认 → 写入 _Memory/distill/
    ↓
第 3 钩 · 日志：记录本次会话的操作日志到 _Memory/history/
    ↓
第 4 钩 · 论语：记录重要决策和共识到 _Memory/history/论语/
    ↓
第 5 钩 · 收摊报告：生成收摊报告，汇报本次会话的记忆变更
```

## 五、设计原理与学术对应

| 记忆设计 | 学术论文对应 | 核心概念 |
|---------|------------|---------|
| 四层记忆分工 | 文件本体公理（公理二） | 文件是记忆的权威载体 |
| 锚定抗衰减 | 记忆治理三功能（论文 §4.3.2） | 记忆从存储介质升格为治理工具 |
| 认知闸门 | 认知熵治理（论文 §5） | 过滤低价值信息，控制认知熵 |
| 算力聚焦 | 经济性论证（论文 §7） | 基础设施趋近于零，成本结构重构 |
| 收摊五钩 | 常态化裁决闭环（论文 §4.5） | 规则层固定环节，不是异常兜底 |
