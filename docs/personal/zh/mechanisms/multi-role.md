# 多角色协作机制（multi-role）
> **语义形态**：机语义（机制翻译层·How）

> **定位**：个人生产力场景的多角色分工机制——让一个 AI 在不同规则约束下扮演不同角色，通过**文件流转**完成复杂生产（书稿/报告/代码/研究等需要"分工+审校"的产出）。
> **原则**：多角色是执行层分工，**裁决权永远在人**（100% 人决断权母公理不变）。
> **经验来源**：设计者真实实践（45 万字书稿生产·主控/编辑/执行/审稿四角色 30 天协作）——详见 [examples/end-to-end/01-book-production.md](../../../../examples/end-to-end/01-book-production.md)。

---

## 一、为什么需要多角色

单角色长跑有三个无法回避的问题：

1. **自审盲区**——AI 自己审自己，容易自我确认（"伪外部审议"不可靠，必须人裁）；
2. **风格漂移**——长周期生产（30 天+）中，术语、文风、格式会逐渐走样；
3. **质量无把关**——产出后没有独立检查环节，错误直达最终交付。

多角色把"生产"与"检查"分开，让质量问题在环节间被拦下——**质量不是靠自觉，是靠流程**。

> **关键认知**：多角色不是"多个 AI 实例"，是"**一个 AI 在不同规则约束下扮演不同角色**"。不依赖多实例调度，不依赖消息总线——只有文件和规则。

## 二、角色定义（四角色）

| 角色 | 职责 | 权限边界 |
|------|------|---------|
| **主控** | 统筹全局：定目标、拆任务、派活、审定稿、裁决角色间争议 | 最高执行权 · 不替代人裁 · 重大争议必须提交人 |
| **编辑** | 内容质量：审改执行产出、统一风格与术语、提修改意见 | 对执行产出的修改权 · 不改目标定义 |
| **执行** | 具体生产：写初稿、查资料、落盘、按意见修改 | 只产出 · 不自审自裁 · 修改按编辑/主控意见 |
| **审稿** | 终审：交叉检查、出问题清单、验证一致性 | **只检不判** · 问题提交主控/人 · 不直接改 |

> 角色可增减（如增加"数据员"），但**四角色闭环（生产→检查→审校→定稿）不可省**——省掉任何一环，多角色就退回单角色。

## 三、文件即接口

角色之间**不靠对话流转，靠约定目录的文件流转**——文件在，流程就在；下次启动装载即恢复。

### 目录约定（示例，可按项目调整）

```
_Work/               # 工作区（角色间流转的中间文件）
├── 主控/            # 大纲、任务分派、定稿
├── 执行/            # 初稿、素材
├── 编辑/            # 审改稿、意见
└── 审稿/            # 问题清单、终审结论
_Output/             # 最终产出（定稿）
```

### 指令状态协议（_Directives/ 接口）

角色通过指令文件末尾追加状态行响应，格式：`[日期时间][状态标签][角色]`

| 标签 | 含义 |
|------|------|
| `[NEW]` | 主控下发新任务 |
| `[ACK_REC]` | 已收到并理解该指令 |
| `[ACK_DONE]` | 指令执行完毕，产出已落盘 |
| `[FEED_NEED]` | 请求补充信息 |
| `[INFO_ERR]` | 发现明显错误，请求修正 |
| `[INFO_SUG]` | 对此指令有优化建议 |

## 四、协作流程（标准一轮）

```
主控定大纲 → 分派到执行 → 执行写初稿（_Work/执行/）
   → 编辑审改（_Work/编辑/·意见写回）
   → 执行按意见修改 → 主控复核 → 审稿终审（_Work/审稿/·问题清单）
   → 主控定稿 → 落盘 _Output/ → 收摊沉淀（记忆五钩）
```

**要点**：
- 每个环节的产出**必须落盘**——不落盘等于没做（否则下次启动即失忆）；
- 审稿的"问题清单"是**事实与候选**，不是裁决——裁决权在主控与人；
- 一轮完成后，经验（术语表、审稿发现、规则缺口）进入蒸馏层，下一轮自动装载。

## 五、角色纪律（正负清单）

**该做**：
- 角色间交接必须通过文件（可追溯）；
- 发现越界/冲突，先显影后行动，不自行推定；
- 每轮收尾更新蒸馏层（进度、共识、待办）。

**禁止**：
- 执行角色自审自裁（自审盲区）；
- 审稿角色直接修改产出（只检不判）；
- 角色间口头流转（无文件即无证据链）；
- 角色代行人裁决（100% 人决断权不可让渡）。

## 六、与核心机制的衔接

| 机制 | 衔接方式 |
|------|---------|
| 启动序列 | 多角色规则随 `rules/` 装载，角色身份文件可存放于 `templates/identity/` |
| 收摊五钩 | 各角色产出随本次会话统一沉淀（对话记录/蒸馏/日志/论语/备份） |
| 歧义治理 | 角色间冲突=歧义，按"显影→定位→分析→人裁→固化"处理 |
| 事故处置 | 角色越界/冲突事故，按"事故即资产"转化为制度补丁（见端到端案例三） |
| 复用机制 | 角色沉淀的术语表/审稿清单/流程模板登记入复用库，跨项目调用 |
