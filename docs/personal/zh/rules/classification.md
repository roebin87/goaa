# GOAA 规则层 · 五级分类
> **语义形态**：人语义（规则层意图锚）+ 编程语义（可校验数据）

> **理论依据**：基本法——级别由稳定性需求决定，越往上越稳定。
> **🔴 编号≠优先级（防错位声明）**：本文件的 L0-L4 编号=**稳定性/修改门槛**分级（L0 最稳、门槛最高）；**效力优先级**以 IDENTITY 基本法第零条为准（宪法层 > 规则层 > 机制层 > 身份层 > SOUL > Agent_Profile > USER）——两个维度，不可混用。
> **格式决策**：规则=YAML+JSON Schema+CI（数据化·检查）；机制=伪代码+脚本（流程化·执行）。

## 五级分类（稳定性/修改门槛）

| 级 | 定义 | 修改门槛 | 落点 |
|----|------|---------|------|
| **L0 宪法级** | 身份/公理/存亡/物理结构契约/分类定义 | 仅最高决断者明令+修宪程序 | `constitution/`（基本法+哲学+原理） |
| L1 身份级 | 体系身份/能力边界/上下级 | 主人审核+三检 | `identity/` |
| L2 规则级 | 规则（写什么） | 主人审核+三检 | `rules/` |
| L3 机制级 | 机制（怎么验/怎么执行） | 主人审核+三检 | `mechanisms/` |
| L4 任务/参考级 | 具体指令（临时）/参考资料 | 上级指令/自由 | 随任务/`examples/`、`docs/` |

> **层级-权限映射**：L0/L1/L2/L3 的修改权=主人（或主人授权的审核者）；L4=执行者自由。与身份层三级权限（L1 全自动/L2 先做后报/L3 审批前置）打通：改 L0-L3 属审批前置，改 L4 属先做后报。

## 规则生产流程

- 规则生产=生产流程实例化：问题→普适判定→课题→探讨→审议→定稿→落地
- 验证：写出≠生效，须过 Rule Effect-Gate（见 validation.md）

## 规则生命周期状态

```
草案 → 待校验 → 已生效 → 待修订 → 已失效
```

- 每条规则带状态字段（见 rules.yaml `state`）；
- 已失效规则进 `deprecated_rules` 保留记录，不删改（全链路留痕）。

## 规则引用规范

- 统一格式：`[R001] 人100%决断权`（ID + 名称）；
- 所有机制/记忆/身份文件引用规则时用标准格式，方便 validator 死链检测与一致性校验。
