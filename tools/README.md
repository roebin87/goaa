## validator.py (consistency validator · generic)

**Run**:
- `python3 tools/validator.py` — core-component check (run inside the repo)
- `python3 tools/validator.py --memory` — **memory health check** (run in a deployed workspace · checks the four memory layers, distillation, owner profile, log continuity — making "files are memory" verifiable)

**Generic scope**:
1. Directory structure (core-component dirs) · core file existence (constitution two + rules + mechanisms + methodologies + DEPLOY) — hard check, FAIL-level;
2. Constitution semantic sync (basic law ↔ design principles key concepts) — WARN-level;
3. **YAML schema compliance** (rules.yaml required sections + rule-id uniqueness) — FAIL-level (enhanced 2026-08-26);
4. **Dead-link / reference check** (`[Rxxx]` rule references must be defined) — FAIL-level (enhanced 2026-08-26);
5. Memory health (`--memory`) — four memory layers, distillation, owner profile, log continuity, plus **append-only hash baseline for the chronicle layer** (enhanced 2026-08-26);
6. PASS/FAIL verdict with details.

**Boundary**: internal custom capabilities (directory read-only permission enforcement, deep semantic checks) are not yet open-sourced (core stable version 1.0; core design changes require review).

## init.py (workspace initialization checker)

**Function**: Checks GOAA workspace directory structure completeness, creates missing required directories and empty files, generates initialization report.

**Run**:
- `python3 tools/init.py` — check mode (check only, no modifications)
- `python3 tools/init.py --fix` — fix mode (auto-create missing dirs and empty files)
- `python3 tools/init.py --workspace <path>` — specify workspace path

**Checks**:
1. Required directories (20): constitution/identity/rules/mechanisms/methodologies/templates/examples/tools/docs/_Memory (4 layers)/_Work/_Output
2. Required files (20): README.md + constitution 2 + identity 3 + rules 3 + mechanisms 8 + tools 2
3. Optional files (10): owner profile/DEPLOY/CONTRIBUTING/SECURITY/CODE_OF_CONDUCT/LICENSE/CITATION/VERSION/AGENTS/STRUCTURE/BENCHMARK

**Note**: `--fix` only creates empty files, doesn't write content. Download full template files from GOAA repository.

## shutdown.py (shutdown helper)

**Function**: Assists shutdown five hooks — backs up key governance files, generates shutdown report template, checks shutdown completeness.

**Run**:
- `python3 tools/shutdown.py` — full mode (backup + report + completeness check)
- `python3 tools/shutdown.py --backup-only` — backup only mode
- `python3 tools/shutdown.py --workspace <path>` — specify workspace path

**Shutdown five hooks**:
1. **Soul backup** (hook 1): auto-backup constitution/identity/rules to `_Memory/history/backup/`
2. **Distill** (hook 2): generates report template, AI fills session essence
3. **Log** (hook 3): records log file path in report, AI confirms
4. **Analects** (hook 4): records analects file path in report, AI confirms
5. **Shutdown report** (hook 5): generates full report template with memory changes/pending adjudication/next startup key points

**Note**: This is a helper tool. Core shutdown content (distill, log, analects) is generated by AI assistant. Full process see [mechanisms/shutdown.md](../docs/personal/en/mechanisms/shutdown.md).

## rule-conflict-check.py (rule conflict detector)

**Function**: Scans all rule files in rules/, detects duplicate rule IDs, same trigger conditions, mutually exclusive instructions, dead references, generates conflict report.

**Run**:
- `python3 tools/rule-conflict-check.py` — detection mode
- `python3 tools/rule-conflict-check.py --workspace <path>` — specify workspace path

**Detection**:
1. **Duplicate rule IDs**: rules with same ID (FAIL-level)
2. **Same trigger conditions**: multiple rules with same trigger (potential conflict · WARN-level)
3. **Mutually exclusive instructions**: opposing instructions for same target (e.g., "allow" vs "deny" · heuristic · WARN-level)
4. **Dead references**: `[Rxxx]` references pointing to non-existent rules (FAIL-level)

**Note**:
- Static detection only, doesn't modify rule content
- Detected conflicts must be adjudicated by human (owner), AI cannot resolve on its own
- Adjudication process see [mechanisms/ambiguity-governance.md](../docs/personal/en/mechanisms/ambiguity-governance.md)
- Mutex instruction detection is heuristic, not exhaustive, may miss or false-positive
